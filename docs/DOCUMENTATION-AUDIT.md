> **How to read this file.** Everything between the `BEGIN GENERATED` / `END GENERATED`
> markers below is derived from the tree by `scripts/doc_audit.py` at the commit that
> ships it. `make verify` composes `make docs-audit-check`, which fails if the committed
> block has drifted. Everything outside the markers is hand-authored history and is
> **not** regenerated: it records what a particular dated pass did and why, which a
> generator cannot know.
>
> That split is deliberate, and so is the warning that comes with it. A generated block
> legitimises whatever the tree currently says, including damage: if hand-authored prose
> outside the markers is deleted and the links in it go with it, regeneration will make
> the link count agree with the loss and report `pass`. Review the prose in a diff, not
> by trusting the block.
>
> **Why this file has a generator at all.** It did not have one, and the counts had
> drifted badly: it claimed "3 test files (2 test modules + `tests/__init__.py`)" against
> 33 files under `tests/`, "architecture and interfaces | 12" against 15 files under
> `docs/adr/`, and "safety, privacy, accessibility, and audits | 3" against 5. Every one
> of those numbers sat in a row marked `pass`. A document whose purpose is to show that
> this project's process claims are real was itself a validation surface reporting
> success about records it no longer inspected.
