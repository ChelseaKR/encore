# Internationalization & localization

i18n status: N/A
Reason: No user-facing strings exist at M0; this flips to Applies at M2 with the first UI string.

Encore declares catalog infrastructure from day one but ships **English-only at
launch**, per the portfolio's Internationalization Standard (I18N-02, which requires
stating status + reason rather than leaving the question silent) and the phased
i18n approach already in flight across this portfolio.

Declared: 2026-07-05 · Reviewer: encore maintainer (Chelsea Kelly-Reif)

## Why English-only at launch

Encore is a nights-and-weekends personal project (`encore-plans/08-risks-and-counters.md`
R7: standards overhead vs. hobby-scale scope). All of Encore's user-facing text —
the onboarding wizard, review queue, notification templates, feed content — doesn't
exist yet at M0. Building the gettext extraction pipeline and a second full
translation *before* there's any English text to translate would be scaffolding
ahead of the product it serves. Spanish parity is scheduled **post-v1**, once the
UI strings exist and stabilize enough that translating them isn't wasted work on
strings that are about to change.

## What is (and is not) translated today

Nothing — there is no user-facing string in the M0 scaffold (`/livez`/`/readyz`
return fixed JSON keys, not display text). This file exists so the "silent omission
is a defect" rule (I18N-02) has an explicit, dated answer instead of an absence.

## The seam (planned)

When the onboarding wizard (F6) lands at M2, all user-facing strings will route
through a single gettext seam (`src/encore/i18n.py`, mirroring the pattern already
proven in this portfolio's `ledger` project) from the first string written, so EN/ES
parity work later is additive rather than a retrofit.

## Gates (planned, join `make verify` when the seam exists)

| Gate | What it checks | Joins at |
|---|---|---|
| G2-lite | Extraction template (`messages.pot`) committed & current | M2 (first UI strings) |
| G7 | Every `.po` compiles cleanly (`msgfmt --check`) | Post-v1 (ES translation begins) |
| G6 | EN/ES key-parity | Post-v1 |
| G5 | Completeness + placeholder parity | Post-v1 |
| G3 | BCP 47 / RFC 5646 tag validity | Post-v1 |

## Scope not yet covered (honest boundaries)

Nothing is implemented yet. This document itself is the M0 deliverable: a dated,
reasoned declaration that English-only is a deliberate, scoped decision, not an
oversight — re-verify this file's status at each milestone exit per
`docs/ROADMAP.md`.
