## Why English-only at launch

Encore is a nights-and-weekends personal project (`encore-plans/08-risks-and-counters.md`
R7: standards overhead vs. hobby-scale scope). All of Encore's user-facing text —
the onboarding wizard, review queue, notification templates, feed content — does not
exist in the current F0 storage state. Building the gettext extraction pipeline and a second full
translation *before* there's any English text to translate would be scaffolding
ahead of the product it serves. Spanish parity is scheduled **post-v1**, once the
UI strings exist and stabilize enough that translating them isn't wasted work on
strings that are about to change.

## What is (and is not) translated today

**Routed through the seam:** every string in `src/encore/notify/render.py` — the
notification subject and body a user reads in ntfy/Discord/email, and the test
message `encore channels test` fires. These are the project's first user-facing
strings, and they ship wrapped from the first commit rather than retrofitted.

**Deliberately not routed:** `/livez` and `/readyz` JSON keys, log lines, CLI
diagnostics, and error text written for the operator. Those are machine and
operator surfaces; translating them would obscure grep-ability without helping a
single end user.

**Translated into:** nothing yet. English source strings are returned unchanged
because no second catalog exists. Spanish parity remains scheduled post-v1, once
the F6 wizard's strings exist and stabilize.

## The seam (live since 2026-08-01)

`src/encore/i18n.py` wraps `gettext` with a memoized catalog lookup;
`$ENCORE_LOCALE` and `$ENCORE_LOCALE_DIR` select and locate catalogs, which live
at `src/encore/locales/<locale>/LC_MESSAGES/encore.mo`. Call sites use `_()` and
`_n()` with **named** `%(placeholder)s` substitutions, never positional ones, so
a translator can reorder them.

`tests/test_i18n.py` compiles a pseudolocale catalog at runtime and asserts the
renderer picks it up — without that, "the seam exists" is unfalsifiable, since an
English-returning `_()` looks identical whether it consults a catalog or not.

## Gates

| Gate | What it checks | Status |
|---|---|---|
| G2-lite | Extraction template (`src/encore/locales/encore.pot`) committed & current | **Live** — `make i18n-check` in `make verify` + CI (2026-08-01) |
| G7 | Every `.po` compiles cleanly | Deferred — no `.po` exists to compile |
| G6 | EN/ES key-parity | Post-v1 (needs a second catalog) |
| G5 | Completeness + placeholder parity | Post-v1 (same) |
| G3 | BCP 47 / RFC 5646 tag validity | Post-v1 (same) |

G2-lite compares the *set* of translatable strings, not line numbers: the template
is extracted with `--no-location --sort-output --omit-header`, so moving a function
does not fail the gate but adding or deleting a user-facing string does. G7 will be
implemented with Babel's `pybabel compile` rather than GNU `msgfmt` — same check,
one fewer non-Python build dependency.

## Scope not yet covered (honest boundaries)

No HTML/template surface exists yet, so no template extraction rule is configured
in `babel.cfg`; it joins when the F6 wizard's Jinja templates land. Number, date,
and currency formatting are not localized (encore displays MusicBrainz's date
strings verbatim, by design — see `docs/adr/0012`). Re-verify this declaration at
each milestone exit per `docs/ROADMAP.md`.
